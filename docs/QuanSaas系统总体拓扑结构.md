# QuantSaaS 系统总体拓扑结构

> 版本：v0.1 | 日期：2026-05-26 | 视角：经验交易员 × 系统架构

---

## 一、系统定位

QuantSaaS 是一个面向专业量化交易团队的 **策略研究→回测→实盘** 全链路 SaaS 平台。核心哲学：

- **数学先行**：策略必须有可证明的数学基础，拒绝"感觉好用"的黑箱
- **进化驱动**：参数空间探索不依赖人工调参，由进化计算引擎自动寻优
- **延迟分层**：研究层容忍高延迟，执行层追求微秒级确定性
- **风险优先**：收益最大化永远排在风险约束满足之后

## 三、核心模块说明

### 3.1 纯粹策略数学引擎 (Math Engine)

策略的**数学骨架**所在。详见 [纯粹策略数学引擎.md](./纯粹策略数学引擎.md)

职责：
- 因子定义语言 (Factor DSL) — 声明式描述 alpha 因子
- 信号生成器 — 将因子映射为 [-1, +1] 区间的持仓倾向
- 组合优化求解器 — 均值方差、CVaR、风险平价等
- 统计检验套件 — t-test、Bootstrap、Walk-Forward、Monte Carlo

### 3.2 进化计算引擎 (Evo Engine)

策略参数的**自动寻优**装置。详见 [进化计算引擎.md](./进化计算引擎.md)

职责：
- 遗传算法 (GA) / 差分进化 (DE) 框架
- 多目标帕累托优化 (NSGA-II/III)
- 种群隔离 + 岛屿迁移模型
- 过拟合检测 — IS/OOS Sharpe 分裂测试

### 3.3 回测引擎集群 (Backtest Farm)

- **事件驱动** tick-by-tick 回测（研究精度）
- **向量化** 批量回测（参数扫描速度 ×1000）
- 滑点模型：固定点差 / 冲击成本模型 / LOB 模拟
- 成本模型：手续费 / 借贷利率 / 资金费率
- 并行调度：跨节点 Ray 集群，单次进化代际并行 1000+ 回测

### 3.4 策略注册表 (Strategy Registry)

所有通过风险审计的策略版本的**不可变记录**：

```
strategy_id: uuid
version: semver (自动递增)
math_fingerprint: sha256(因子定义 + 信号逻辑)
param_snapshot: {参数名: 值, 优化约束, 最终适应度}
oos_metrics: {sharpe, max_dd, calmar, hit_rate}
risk_signature: {max_position, max_notional, stop_loss_rule}
deployed_at: null | timestamp
status: draft | validated | live | deprecated
```

### 3.5 实时数据层

#### 行情接入网关
- WebSocket + FIX 双通道，自动故障切换
- 数据质量：异常检测（价格跳变 > 5σ 触发告警）、成交量一致性校验
- 归一化：多交易所 tick 数据统一为内部 `UnifiedTick` 格式

#### 因子计算流水线 (Factor DAG)
- 有向无环图结构，支持因子依赖声明
- 增量计算：每个 tick 只重算脏节点
- 延迟预算：单链路 < 500μs（研究模式），< 50μs（实盘模式）

#### 订单簿重建引擎
- L2 快照 + 增量 diff 重建完整 LOB
- 支持回测时用历史 LOB 数据模拟真实成交

### 3.6 执行层

#### 风控防火墙 (Risk FW)

**双重门禁架构**：

| 门禁 | 类型 | 延迟目标 | 检查项 |
|------|------|---------|--------|
| 预交易风控 | 同步阻塞 | < 10μs | 仓位上限、保证金充足性、最大单笔亏损 |
| 实时监控 | 异步旁路 | < 1ms | 日内亏损、相关性集中、因子暴露 |

风控参数由策略注册表中的 `risk_signature` 驱动，**不允许运行时手动覆盖**。

#### 订单路由引擎 (OMS Router)
- 智能拆单：TWAP / VWAP / POV / IS 算法
- 多交易所聚合：价格优先、流动性优先两种路由模式
- 订单状态机：`NEW → PENDING → PARTIAL → FILLED / CANCELLED / REJECTED`

## 四、数据流向

### 研究流（离线）
```
历史数据仓库
    → 因子计算 (批量)
    → Math Engine (信号生成)
    → Evo Engine (参数优化)
    → 回测集群 (种群评估)
    → 策略注册表 (持久化)
```

### 实盘流（在线）
```
交易所 WebSocket
    → 行情网关 (归一化)
    → 因子 DAG (增量计算, <500μs)
    → Math Engine (信号输出)
    → 风控防火墙 (<10μs)
    → OMS 路由 (拆单)
    → 交易所适配器 (下单)
```

## 五、技术选型

| 层次 | 组件 | 技术选型 | 理由 |
|------|------|---------|------|
| 研究层 | Math Engine | Python (NumPy/Polars) | 生态最丰富，研究效率优先 |
| 进化引擎 | Evo Engine | Python + Ray | 并行调度简单，集群扩展线性 |
| 回测集群 | Vectorized | Rust + PyO3 | 核心循环性能敏感 |
| 实时因子 | Factor DAG | Rust | 延迟确定性要求 |
| 执行层 | OMS / Risk | Rust | 微秒级延迟，内存安全 |
| 消息总线 | 内部通信 | NATS JetStream | 低延迟，持久化可选 |
| 时序存储 | 历史数据 | QuestDB | SQL 接口，列式，时序优化 |
| 热数据 | L1/L2缓存 | Redis Streams | 订单簿快照、实时因子值 |
| 注册表 | 策略元数据 | PostgreSQL | ACID，支持复杂查询 |
| 编排 | 任务调度 | Temporal | 进化代际工作流持久化 |

## 六、部署拓扑

### 研究环境（云端弹性）
```
Kubernetes Cluster (GKE / EKS)
├── Research Namespace
│   ├── Math Engine Pod × N (CPU 密集)
│   ├── Evo Engine Controller Pod × 1
│   └── Ray Worker Pool (自动扩缩 0→100)
├── Data Namespace
│   ├── QuestDB StatefulSet
│   ├── Redis Cluster
│   └── Kafka Cluster
└── Registry Namespace
    └── PostgreSQL (HA, 3-node)
```

### 执行环境（共置低延迟）
```
专用物理服务器 (与交易所同城机房)
├── Risk FW (CPU 核心绑定, 实时内核)
├── OMS Router (DPDK 网络栈)
├── Factor DAG (L1/L2 缓存命中优化)
└── Exchange Adapters (FIX Engine)
```

## 七、关键设计约束

1. **策略数学定义与参数分离**：策略逻辑一旦注册不得修改，只能新建版本
2. **回测 = 实盘代码路径**：Math Engine 的信号生成代码在回测和实盘中共享同一实现，消除"回测好实盘差"的根本原因
3. **进化器无法接触执行层**：参数优化结果必须经过人工审核 + 风险签名才能推送到实盘
4. **可观测性优先**：每个模块输出 OpenTelemetry trace，全链路延迟可查
5. **幂等性**：所有订单操作携带幂等键，网络重试不产生重复下单
