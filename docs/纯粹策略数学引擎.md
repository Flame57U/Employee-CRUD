# 纯粹策略数学引擎 (Pure Strategy Math Engine)

> 版本：v1.0 | 日期：2026-05-27 | 标的：A股宽基ETF / 黄金ETF

---

## 第 0 章：引擎身份

### 0.1 核心定义

纯粹策略数学引擎是一个**无状态纯函数转换器**。

```
Step(StrategyInput) → StrategyOutput
```

引擎不持有任何内部状态。每次 `Step()` 调用读入完整的当前快照，产出完整的交易意图，不依赖上次调用的任何内存变量。所有 K 线历史、账户状态、策略参数均通过 `StrategyInput` 显式传入。

### 0.2 接口契约

**输入 StrategyInput：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `closes` | `[]float64` | 收盘价序列（时序升序，最新在末尾） |
| `timestamps` | `[]int64` | 对应时间戳（Unix 秒） |
| `portfolio` | `PortfolioState` | 当前资产三态快照 |
| `params` | `Chromosome` | 当前生效的染色体参数包 |

> OHLCV 到 `[]float64` 的降级在 ACL 外圈完成，策略内核不接触 `quant.Bar`。

**输出 StrategyOutput：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `macro_orders` | `[]Order` | 宏观引擎产生的底仓买入意图 |
| `micro_orders` | `[]Order` | 微观引擎产生的浮动仓交易意图 |
| `release_events` | `[]ReleaseEvent` | DeadHold → FloatHold 语义转换事件 |
| `market_state` | `MarketState` | 本次 tick 识别的市场状态（审计用） |

### 0.3 铁律复述（继承自系统拓扑文档第 7 章）

1. **复利前置**：`Step()` 产出的每一个动作必须可论证其如何通过权益正反馈驱动资金规模增长。不满足此条件的设计不得进入实现。
2. **同构执行**：回测与实盘调用同一个 `Step()` 实现。内部禁止 `if isBacktest { ... }` 类分支。
3. **策略纯净**：`Step()` 内部绝对禁止定时器、网络请求（HTTP/WebSocket/gRPC）、数据库读写、任何文件 I/O。
4. **OHLCV 剥离**：策略内核只依赖 `[]float64 closes` + `[]int64 timestamps`，OHLCV 聚合结构降级在外圈 ACL 完成。
5. **无量纲计算**：所有价格相关计算使用对数收益率或比率，禁止用绝对价格做跨标的比较。
6. **三态不混用**：`DeadHold` / `FloatHold` / `ColdSealedHold` 语义严格隔离，不得跨态操作。
7. **释放不下单**：`DeadHold → FloatHold` 的语义转换只改变 SaaS 侧账本，不向 Agent 下发任何 `TradeCommand`。

## 第 1 章：资产结构三态（Portfolio State）

### 1.1 三态定义

| 状态标识 | 中文 | 语义 | 进出规则 |
|---------|------|------|---------|
| `DeadHold` | 底仓 | 宏观引擎吸入的长期持仓 | 只进不出，仅满足第 6 章全部释放条件后可转为 FloatHold |
| `FloatHold` | 浮仓 | 微观引擎管理的交易性持仓 | 可买可卖，受微观引擎目标权重约束 |
| `ColdSealedHold` | 冷封存 | 永久冻结持仓 | 永不释放、永不参与任何运算，策略不可操作 |

`ColdSealedHold` 用于存放用户手动冻结的特殊份额（如锁定期持仓），初始化时写入账本后对引擎透明。

### 1.2 核心公式

设：
- `V_dead` = DeadHold 当前市值（CNY）
- `V_float` = FloatHold 当前市值（CNY）
- `V_cold` = ColdSealedHold 当前市值（CNY）
- `C` = 当前可用 CNY 现金

**总权益（TotalEquity）：**

```
E_total = V_dead + V_float + V_cold + C
```

**保底储备（ReserveFloor）：**

```
R_floor = E_total × macro_reserve_pct
```

保底储备是宏观引擎预留的最低现金缓冲，确保在极端行情下仍有弹药可用，不得动用于任何下单。

**可动用现金（SpendableCNY）：**

```
C_spend = max(0, C - R_floor)
```

宏观买入与微观买入均从 `C_spend` 内扣减。`C_spend` 实时更新，同一 tick 内宏观先扣、微观后扣。

**当前微观权重（CurrentMicroWeight）：**

```
w_micro_cur = V_float / E_total
```

微观浮仓占总权益的当前比例，供微观引擎计算目标偏差使用。

### 1.3 参数语义

| 参数 | 类型 | 默认值 | 硬边界 | 语义 |
|------|------|--------|--------|------|
| `macro_reserve_pct` | float64 | 0.05 | [0.02, 0.20] | 宏观保底现金占总权益比例；可进化 |

## 第 2 章：市场状态感知层

### 2.1 设计意图

市场状态感知是引擎的第一道信息过滤器。三种市场状态下，宏观与微观引擎的行为规则截然不同。本章定义三个互斥状态的判断逻辑，以及各状态下的行为约束。

### 2.2 三态定义与行为约束

| 状态标识 | 中文 | 宏观行为 | 微观行为 |
|---------|------|---------|---------|
| `BULL` | 牛市 | 按正常 DCA 节奏吸纳底仓 | 信号全量生效，Sigmoid 天平自由摆动 |
| `BEAR` | 熊市 | 乘数加速定投（× `bear_macro_boost`） | 多头信号乘以 `bear_micro_scale` 缩减；禁止 DeadHold 释放 |
| `QUIET` | 安静态 | 静默，不产生宏观订单 | **微观粉尘订单强制归零**（见 2.4 节） |

### 2.3 状态判断逻辑

使用三条 EMA 构成趋势坐标系：

```
EMA_fast_t  = EMA(closes, N_ema_fast)
EMA_mid_t   = EMA(closes, N_ema_mid)
EMA_slow_t  = EMA(closes, N_ema_slow)
```

约束：`N_ema_fast < N_ema_mid < N_ema_slow`（EMA 顺序约束，见第 7 章结构约束 C_struct_1）

**归一化波动率（ATR）：**

```
atr_n_t = EMA(|close_t - close_{t-1}| / close_{t-1}, N_atr)
```

**状态判断（优先级由上至下，首个命中即停止）：**

```
① QUIET（优先判断）：
     atr_n_t < atr_quiet_threshold
     AND |close_t - EMA_mid_t| / EMA_mid_t < quiet_band

② BEAR：
     close_t < EMA_slow_t            # 价格位于慢线下方
     AND EMA_fast_t < EMA_mid_t      # 快线在中线下方（趋势下行）

③ BULL（兜底）：
     不满足上述任一条件
```

### 2.4 安静态粉尘订单归零规则

当 `market_state == QUIET` 时，微观引擎计算出的理论订单须经过额外门槛：

```
if market_state == QUIET:
    micro_orders = []   // 强制清空，无论理论金额多少
```

这是楔形区过滤（第 5.3 节）条件 C 的系统级执行，确保安静态下不产生任何微观摩擦成本。

## 第 3 章：信号与目标函数框架

### 3.1 统一信号

引擎的所有买卖决策均源于一个综合信号 `S_t ∈ [-1, +1]`：

```
S_t > 0  → 多头倾向（超配资产）
S_t < 0  → 空头倾向（减持资产，转持现金）
|S_t|    → 信号强度（置信度）
```

宏观与微观引擎对同一 `S_t` 做不同维度的响应：
- **宏观引擎**：只关注价格对历史高点的深度折扣（见第 4 章），不直接使用 `S_t`
- **微观引擎**：以 `S_t` 为输入，通过 Sigmoid 映射到目标浮仓权重（见第 5 章）

### 3.2 三分量综合信号

```
S_t = normalize(α_trend × S_trend_t + α_reversion × S_revert_t + α_vol × S_vol_t)

约束：α_trend + α_reversion + α_vol = 1，α_i ≥ 0（归一化处理，非硬拒绝）
```

**趋势分量（S_trend）：**

以 ATR 归一化的快慢 EMA 差，捕捉价格趋势的方向与强度：

```
S_trend_t = clip(
    (EMA_fast_t - EMA_slow_t) / (atr_n_t × EMA_slow_t),
    -1, +1
)
```

**均值回归分量（S_revert）：**

价格偏离中轨时的反向信号，低于中轨做多、高于中轨做空：

```
z_t         = (close_t - EMA_mid_t) / (EMA_mid_t × atr_n_t × revert_scale)
S_revert_t  = -clip(z_t, -1, +1)
```

**波动率分量（S_vol）：**

波动率低于基线时轻度看多（低波建仓），高于基线时轻度看空（高波收敛）：

```
S_vol_t = clip(1 - atr_n_t / atr_baseline, -1, +1)
```

最终 `S_t` 经过 `clip(-1, +1)` 确保始终在合法范围内。

### 3.3 MPC 概念层

策略的目标函数可理解为一个有限域模型预测控制（MPC）问题：

```
min   Σ_{k=1}^{H} [ λ_risk × Var(r_{t+k}) - λ_return × E[r_{t+k}] + λ_cost × TC_{t+k} ]

s.t.  w_t ∈ [w_micro_min, w_micro_max]
      |w_{t+1} - w_t| × E_total ≤ C_spend   （受可动用现金约束）
```

其中 H 为预测视野（由信号衰减速度决定），TC 为交易成本项。

在当前实现中，MPC 以闭合形式近似：用第 5 章的 Sigmoid 目标权重替代完整的滚动优化。这大幅降低了计算复杂度，同时保留了"距离目标权重越远、调仓意愿越强"这一核心经济含义。

## 第 4 章：宏观引擎

### 4.1 设计原则

宏观引擎的核心使命是**长期低成本累积底仓**。通过系统化的动态定投（DCA），在价格相对历史高点出现折扣时加速吸筹，在价格平稳时维持匀速买入，以底仓的持续积累驱动复利。

宏观引擎的约束：
- 只产生 `BUY` 意图，`LotType = DEAD_STACK`
- 不产生任何卖出指令
- 不关注短期价格波动，只关注价格相对历史高点的深度折扣

### 4.2 定投触发条件

宏观引擎按聚合周期（tick）触发，每个 tick 最多执行一次宏观决策：

```
macro_trigger = true  当且仅当：
    (1) market_state ∈ {BULL, BEAR}           // 安静态静默
    AND (2) C_spend > macro_min_order_cny      // 有足够可用现金
    AND (3) ticks_since_last_macro ≥ macro_cooldown_ticks   // 冷却期已过
```

`ticks_since_last_macro` 由 `StrategyInput` 中的 `RuntimeState` 字段携带（SaaS 侧持久化，外圈传入）。

### 4.3 动态 DCA 金额计算

宏观买入金额随价格对历史高点的折扣深度动态放大：

**滚动历史峰值（峰值窗口内收盘价最高值）：**

```
peak_t = max(closes[max(0, t - N_peak_window) : t+1])
```

**价格折扣深度：**

```
dd_t = (peak_t - close_t) / peak_t    ∈ [0, 1)
```

**折扣乘数（凸函数，折扣越深买入越多）：**

```
dca_multiplier_t = 1 + dca_boost_coef × (dd_t / dca_dd_scale)^dca_convexity
```

- `dd_t = 0`（价格在峰值）：乘数 = 1，正常基础定投
- `dd_t = dca_dd_scale`（跌至校准折扣深度）：乘数 = 1 + dca_boost_coef
- `dca_convexity > 1`：凸函数保证折扣越深、加速度越大

**本次宏观买入金额：**

```
macro_order_cny = min(
    C_spend × macro_base_alloc_pct × dca_multiplier_t × state_multiplier,
    C_spend × macro_max_single_pct    // 单次上限，防止一把梭哈
)
```

其中市场状态乘数：

| market_state | state_multiplier |
|-------------|-----------------|
| `BULL` | 1.0 |
| `BEAR` | `bear_macro_boost`（默认 1.5） |
| `QUIET` | 0（不触发，macro_trigger 已拦截） |

### 4.4 宏观引擎输出

当 `macro_trigger == true` 且 `macro_order_cny > macro_min_order_cny` 时，输出：

```
MacroOrder {
    action:     BUY
    lot_type:   DEAD_STACK
    amount_cny: macro_order_cny
    symbol:     [策略绑定标的]
}
```

否则 `macro_orders = []`。

## 第 5 章：微观引擎

### 5.1 Sigmoid 动态天平

微观引擎以 Sigmoid 为骨架构造动态天平：**外力（市场信号）** 与 **弹簧恢复力（仓位偏置）** 在 Sigmoid 内部叠加，输出当前 tick 的目标浮仓权重 `w_target ∈ [0, 1]`。

设计哲学：
- `Signal`：外力，来自市场（综合信号 `S_t`，第 3 章）
- `InventoryBias`：弹簧恢复力，当前浮仓权重相对中性（0.5）的偏离
- `Beta`：弹簧刚度（Sigmoid 陡峭度），越大对信号越敏感
- `Gamma`：决定弹簧是否启用（0 = 纯趋势跟随，>0 = 引入均值回归张力）
- `VolatilityRatio`：楔形过滤的开关——活跃期放宽下单，安静期粉尘归零

**信号锚定（不可进化常量）：**

引擎使用固定窗长的 EMA 与 σ 锚定无量纲信号，避免染色体爆炸：

```
anchor_t  = EMA(closes, MicroSignalEMABars=20)
sigma_t   = max( StdDev(closes, MicroSignalStdDevBars=20),  sigma_floor )

if sigma_t == 0:  跳过本次决策
```

`sigma_floor` 是染色体可进化的最小标准差地板，防止零波动时分母失效。

**无量纲信号：**

```
S_t = clip( (close_t - anchor_t) / (anchor_t × sigma_t),  -5, +5 )
```

符号约定：`S_t > 0` 表示价格高于锚（**超买，目标权重应下调**）；`S_t < 0` 表示价格低于锚（超卖，目标权重应上调）。

**Sigmoid 目标权重公式：**

```
EffectiveBeta  = max(0.01, beta × BetaMultiplier)
InventoryBias  = clip(CurrentWeight, 0, 1) - 0.5
Exponent       = EffectiveBeta × S_t + gamma × InventoryBias
w_target_t     = clip( 1 / (1 + exp(Exponent)),  0,  1 )
```

其中：
- `BetaMultiplier` 由市场状态感知层注入（BULL/BEAR = 1.0，可被状态层覆盖）
- 正信号 → `Exponent > 0` → `w_target → 0`（卖压主导）
- 负信号 → `Exponent < 0` → `w_target → 1`（买压主导）
- `InventoryBias > 0`（持仓过高）→ 进一步抑制 `w_target`，体现均值回归弹簧

### 5.2 理论订单计算

**仓位偏差与理论 CNY：**

```
ΔW             = w_target_t - CurrentWeight
TheoreticalCNY = ΔW × TotalEquity
```

- `TheoreticalCNY > 0`：需买入，增持浮仓（受 `SpendableCNY` 在执行层硬约束）
- `TheoreticalCNY < 0`：需卖出，减持浮仓（不足时由硬释放从 DeadHold 补足，见第 6 章）
- `TheoreticalCNY == 0`：无订单输出

### 5.3 楔形区（Wedge）过滤规则

为避免微小波动产生粉尘订单，引擎在 `TheoreticalCNY` 落入楔形区时强制归零或最小化。

**波动率比值（VolatilityRatio）：**

使用两个固定常量窗长的 `MAVAbsChange`（不可进化）：

```
long_mav        = MAVAbsChange(closes, MicroVolRatioLongBars=60)
short_mav       = MAVAbsChange(closes, MicroVolRatioShortBars=10)
VolatilityRatio = clip( short_mav / long_mav,  0.1,  3.0 )    // 数据不足默认 1.0
```

`VolatilityRatio > 1` 表示近端波动相对长期放大（活跃态），`< 1` 表示收敛（安静态特征）。

**三档过滤逻辑：**

```
if |TheoreticalCNY| >= micro_dust_cny:
    OrderCNY = round(TheoreticalCNY)            // 原值直接下单

elif 0 < |TheoreticalCNY| < micro_dust_cny:
    breakthrough = (NOT IsQuiet) AND (
        |ΔW| > delta_weight_wedge  OR
        VolatilityRatio > vol_ratio_wedge
    )
    if breakthrough:
        OrderCNY = sign(TheoreticalCNY) × micro_dust_cny   // 强制最小订单
    else:
        OrderCNY = 0

else:  // TheoreticalCNY == 0
    OrderCNY = 0
```

铁律：`IsQuiet == true` 时楔形区一律归零，不允许突破。

### 5.4 微观引擎输出

```
MicroOrder {
    action:     BUY | SELL          // 由 OrderCNY 符号决定
    lot_type:   FLOATING
    amount_cny: |OrderCNY|          // BUY 时为目标买入金额
    qty_asset:  |OrderCNY| / close  // SELL 时为粗估份额，Agent 侧取整
    symbol:     [策略绑定标的]
}
```

调试输出 `MicroEngineOutput` 同时携带 `TargetWeight / Signal / TheoreticalCNY / OrderCNY / VolatilityRatio`，供 GA 适应度与回测审计使用。

## 第 6 章：DeadHold 释放规则

### 6.1 释放语义

DeadHold → FloatHold 的**语义转换**不产生实际交易指令，仅修改 SaaS 侧 `PortfolioState` 账本的仓位分类，并强制写入审计日志。转换后，对应份额进入 `FloatHold`，可参与微观引擎的交易决策。

> 依据系统拓扑文档铁律第 9 条：释放操作仅在 SaaS 侧更新，不向 Agent 下发任何 `TradeCommand`。

### 6.2 释放触发条件（全部满足方可释放）

| 编号 | 条件名 | 判断公式 | 说明 |
|------|--------|---------|------|
| C1 | 收益条件 | `(close_t / lot.cost_basis - 1) ≥ release_profit_threshold` | 该批次底仓浮盈超过阈值方可释放，防止亏损释放 |
| C2 | 持仓时间条件 | `(t - lot.acquired_at) ≥ release_min_hold_days × 86400` | 底仓持有天数超过最短周期，防止快进快出破坏底仓结构 |
| C3 | 市场状态条件 | `market_state ≠ BEAR` | 熊市中禁止释放，避免释放后份额在低位被微观引擎卖出 |
| C4 | 浮仓容量条件 | `w_micro_cur < w_micro_release_cap` | 当前浮仓权重低于释放上限，防止浮仓因释放而过载 |
| C5 | 现金充裕条件 | `C / E_total ≥ macro_reserve_pct` | 账户现金比例健康，无需保留底仓作为流动性缓冲 |

### 6.3 批次释放机制

底仓按**买入批次（Lot）** 独立记录（cost_basis 与 acquired_at 各批次不同）。每个 `Step()` 调用中：

1. 遍历所有 DeadHold 批次，对每个批次独立判断 C1–C5
2. 满足全部条件的批次按**先进先出（FIFO）**顺序排队
3. 每次 `Step()` 最多释放 `max_lots_per_tick` 个批次（Epoch 参数，出生时固定）

### 6.4 释放输出

```
ReleaseEvent {
    lot_id:       string     // 被释放的底仓批次 ID
    qty_asset:    float64    // 释放份额数量
    from_state:   DEAD_HOLD
    to_state:     FLOAT_HOLD
    release_time: int64      // Unix 时间戳（本次 Step 的 tick 时间）
    audit_note:   string     // "C1-C5 全满足，自动释放"
}
```

## 第 7 章：可进化参数契约（Chromosome）

### 7.1 设计原则

**染色体参数**：参与 GA 代内交叉与变异，由进化引擎在搜索空间中寻找最优值。

**出生点参数（Epoch 参数）**：实例创建时由用户/运营配置并冻结，不进入基因组。变更 Epoch 参数须创建新策略版本，旧版本归档为 `deprecated`。

### 7.3 硬边界约束

所有字段均受 §7.2 表格 `[min, max]` 约束，GA 变异后必须 clip 到合法范围。

以下**结构约束**由 `ClampChromosome` 在变异后强制修复（非硬拒绝，自动收敛到合法形态），不再使用 "适应度 = -∞" 丢弃机制：

```
C_struct_1（EMA 顺序约束，相对论锁）：
    N_ema_fast < N_ema_mid < N_ema_slow
    修复：发现违反则递增方式调整，使三者保持严格升序

C_struct_2（信号权重归一化）：
    alpha_trend + alpha_reversion + alpha_vol → 归一化为 1.0
    修复：三者 clip 后按比例缩放；若三者全为 0 则平分 1/3

C_struct_3（宏观单次金额合法性）：
    macro_base_alloc_pct ≤ macro_max_single_pct
    修复：发现违反则将 base_alloc 下压到 max_single
```

> 历史版本 v1.0 中的 `C_struct_3/C_struct_4`（浮仓权重顺序约束、释放上限约束）随 Sigmoid 动态天平改造（取消 `w_micro_min/w_micro_max`）一并废止；编号已重新整理。

### 7.4 出生点参数（Epoch 参数，不进入基因组）

以下参数在实例创建时配置，启动后冻结。代码层组织为 `SpawnPoint { Policy, Risk }` 两组：

**Policy（资金政策）：**

| 字段名 | 类型 | 语义 |
|--------|------|------|
| `instance_id` | string | 策略实例唯一标识 |
| `symbol` | string | 交易标的代码（如 `510300.SH`、`518880.SH`） |
| `asset_class` | enum | 标的类型（`A_STOCK_ETF` / `GOLD_ETF`） |
| `total_capital_cny` | float64 | 本实例总资金配额 |
| `monthly_inject_cny` | float64 | 每月注资金额（Ghost DCA 对照用） |
| `deadline_ratio` | float64 | 死线兜底比例覆盖 |
| `macro_min_order_cny` | float64 | 宏观最小下单金额（匹配券商最小申购额） |
| `quiet_dust_threshold` | float64 | 安静态粉尘归零绝对下限（与券商手续费结构绑定） |
| `max_lots_per_tick` | int | 每次 tick 最多释放底仓批次数 |
| `release_trigger` | float64 | 释放阈值覆盖 |
| `created_at` | int64 | 实例创建时间戳（Unix 秒） |

**Risk（风险边界）：**

| 字段名 | 类型 | 语义 |
|--------|------|------|
| `fee_rate` | float64 | 单边手续费率（如 0.0001） |
| `global_stop_loss` | float64 | 全局权益回撤硬止损 |
| `max_daily_drawdown` | float64 | 日内回撤上限 |
| `max_consec_lose_days` | int | 最长连续亏损天数 |

> 任何 Epoch 参数的变更，必须创建新策略版本并通过人工审批，旧版本自动归档为 `deprecated`，不允许原地修改。
